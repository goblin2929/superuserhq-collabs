Automation · Augmentation · Agency
Automation. Augmentation. Agency.
Three modes — one AI. Knowing which to reach for is the whole job.
01
Automation.
Human wires a flow. Machine runs it the same way, every time.
Tool
n8n · Zapier · RPA
How it works
Same steps, every run. 100% consistent per step. Deterministic.
Best for
High-volume, predictable, auditable work.
Sales example
Meeting booked → HubSpot deal → nurture sequence → Slack ping to the AE.
02
Augmentation.
Human does the work with AI. You prompt, it helps, you review.
Tool
Claude.ai · Cowork · Claude in Chrome
How it works
You ask, it assists. You stay in the loop every turn.
Best for
Drafting, thinking, research — your brain's co-pilot.
Sales example
"Help me redraft this email for a skeptical CFO — tighter, more ROI-forward."
03
Agency.
Human configures the AI to work independently. Set the rules; it decides the steps.
Tool
Skills & Agents (Claude Code)
How it works
Looks, thinks, decides, adjusts — within boundaries you set.
Best for
Judgment-heavy, messy, novel-input work at scale.
Sales example
"Before every call, read the prospect's last 6 months of emails + 3 calls and draft a brief with likely objections."

How a coding assistant actually works — the inner loop
How a coding assistant works. The inner loop.
When you give Claude Code (or Cowork) a task, it follows the same pattern a human developer would. The model itself just thinks — it's the harness around it that lets it reach into the real world.
Source: Anthropic — "How Claude Code works"
01 · Gather context
Read the error. Find the relevant files. Look up the docs. Figure out what's actually going on.
02 · Formulate a plan
Decide how to fix it. Which code to change. Which tests will prove it's fixed.
03 · Take action
Actually do it. Edit files. Run tests. Run a command. Then loop back to step 1 if the result isn't right.
The key insight: steps 1 and 3 require Claude to reach outside the chat — read files, run shell commands, hit APIs. That's tool use. That's why Code & Cowork exist instead of just chat.

Artifact vs. Skill.
Artifact = a thing produced.  ·  Skill = a process for producing things.
Artifact Skill

Where it livesIn the conversation, Cowork side panelOn disk · ~/.claude/skills/ or a plugin
LifespanPer-conversation · until you publish or save the linkForever · auto-loads every future matching session
Primary useBuild this thing, right nowCodify how to do this kind of thing, repeatedly
Who changes itYou edit it inside the canvasYou version it in Git · team reuses it

They compose. A skill can produce an artifact. /build-dashboard is the skill. The React dashboard it drops into the artifact panel is the output.
Artifact = the deliverable. Skill = the recipe. Pair them.

What is a skill
Anthropic · Agent Skills
Skills are folders of instructions that Claude can discover and use to handle tasks more accurately.
The file
Every skill lives in a SKILL.md file with a name and a description in its frontmatter.
The match
Claude compares your request against every skill's description. When the match is close enough, it activates the skill — automatically.
The point
Teach Claude once. It applies that knowledge every future session that matches — no more repeating yourself.
skills/blog-production/SKILL.md
---
name: blog-production
description: Use when writing blog content — runs the 7-phase production workflow.
---
## Steps
1. Research · 2. Outline · 3. Draft · …

Anatomy of a skill.

SKILL.md — the operation manual
SKILL.md — the operation manual.
Three sections answer when, how, and what.
Frontmatter
name — how Claude refers to the skill.
description — the trigger. Claude matches your prompt against this.
allowed-tools (optional) — restrict which tools the skill can use.
Trigger · Workflow · Output
## Trigger — when the skill should fire.
## Workflow — step-by-step execution.
## Output — expected format and content.
skills/prospect-audit/SKILL.md
---
name: prospect-audit
description: Use when qualifying a new prospect — runs the 12-phase AEO audit and drafts a one-page brief.
allowed-tools: Read, Write, WebFetch, Bash
---
## Trigger
User provides a prospect domain or company name.

## Workflow
1. Fetch domain metrics (scripts/pull-seo.sh)
2. Score against AEO rubric (references/aeo-scoring.md)
3. Draft brief (assets/brief-template.md)

## Output
A one-page markdown brief with recommendations.
Only SKILL.md is required. Everything else is optional — add when the skill needs it.

How to invoke a skill
Three ways a skill activates.
From explicit slash command to auto-invoke when Claude sees the right context.
01 · Slash command
You name the skill directly.
Fastest. Explicit. No ambiguity — you tell Claude exactly which skill to run. Works in Claude Code on your own machine.
tinachu@novastacks ~ % claude
> /prospect-audit acme-corp.com
[skill: prospect-audit · loaded]
[references/aeo-scoring.md loaded]
[running 12-phase audit...]
Best when you know the skill name and want it right now.
02 · Tell Claude
Mention the skill in plain English.
You say it. Claude looks up the skill by name, loads the body, runs it. No command syntax.
"Run the prospect-audit skill on acme-corp.com."
Best when you remember the name but not the exact trigger phrase.
03 · Auto-invoke
Claude picks the skill itself.
You describe the work. Claude scans every skill's description, finds the match, loads it. You never named a skill.
"Qualify acme-corp for us — usual checks."
Best when the team uses different phrasing every time.
How to make #3 reliable — write the description like a scenario
Bad: "Prospect audit tool."  →  Claude can't tell when to use it.
Good: "Use when qualifying a new prospect — runs a 12-phase AEO and SEO audit, drafts a one-page brief. Trigger phrases: 'qualify X,' 'audit X,' 'should we take X on.'"
Include the phrases your team actually uses. The description IS the matching surface.
The description is the trigger. Write it so Claude can find it.

What makes a good skill
What makes a good skill.
Skills are easy to write. Easy to write badly. Five rules separate the two.
TraitGoodBad
01 · Sharp description "Use when writing a monthly affiliate performance report — runs pull → analysis → deck." "Affiliate tool." ← Claude never finds it.
02 · One job One skill = one procedure. Splits naturally by verb. "Do-everything marketing skill." ← nothing triggers cleanly.
03 · Names its inputs "Requires: GA4 property ID, month, affiliate list." Assumes context. ← fails silently on Day 2.
04 · Short body, linked references Steps + a link to references/report-template.md. Loads the ref only if needed. 2,000 lines pasted in the skill body. ← bloats every load.
05 · Testable output "Output: a Google Sheet with columns X / Y / Z + a summary block." "Gives you insights." ← you can't tell if it's wrong.
The description is the trigger. The body is the recipe. References are the pantry — load only when cooking.
A good skill you wrote once → your team runs forever.

How to prevent context rot
✓Trim CLAUDE.md — keep it short; every line costs space every turn.
✓Split procedures into skills — body loads only when invoked, not at startup.
✓Persist plans to PROGRESS.md — on disk, survives every wipe.
✓Run /compact when the session fills — summarises earlier turns; saves space, loses detail.

✓Delegate heavy research to subagents — their own whiteboard; you get a summary.

A full context window produces worse output than a clean one.

The learnings loop — how the agent gets better without retraining
The agent gets better every run. Without retraining.
Remember the hook from the last slide — the tripwire your computer fires when Claude stops. It's not just cleanup. It's how the agent learns.
What happens

The system writes its own notes after each run.

When Claude finishes, a hook fires — a small program your computer runs automatically. It catches what went wrong (or what worked), writes one line to ~/.claude/CLAUDE.md or MEMORY.md, and the next session reads it back. The agent walks in already knowing the lesson.

Why it isn't fine-tuning

No weights. No GPU. No data team.

Fine-tuning retrains the model. Expensive, slow, ML infra. The learnings loop just changes what the model knows before it starts. A shell script can do this. Marketing teams can do this.

What it buys you

The work compounds.

Most agents stay flat — run 10 looks like run 1. This one's measurably sharper at run 10. Every correction logged = one less repeated mistake across every future session. Never let a correction evaporate.

Same mistakes every time
→ Mistakes stop repeating
Needs a data team to improve
→ A text file does the job
Run 10 looks like run 1
→ Run 10 is sharper than run 1
The harness catches mistakes. The loop remembers them. That's why the system gets better the more you use it.
Hook + file = the cheapest learning system you'll ever build.
